# AI 出海营销助手 Demo 技术方案

> 版本：v2.0  
> 日期：2026-11-17  
> 项目：`D:\xm\demo1`  
> 定位：独立前端 Demo，不修改 `D:\work\edou\edou-admin-vue3`

## 1. 结论与范围

本方案采用“前端可演示闭环优先”的实现方式，技术上可行，且与当前项目基础兼容：保留 Vue 3、TypeScript、Element Plus、Pinia、Vue Router、ECharts 和 Mock API，不引入真实后端、数据库、账号权限或真实 LLM。

本次 Demo 必须完整回答五个问题：

1. 客户从哪里来，为什么优先跟进这家？
2. AI 生成什么联系内容，后续如何跟进？
3. 如何由客户需求生成一份短服务方案？
4. 方案如何变成任务，并展示可读的交付物？
5. 如何用目标与实际结果复盘，并生成下一轮动作？

“AI”在本 Demo 中通过 Mock AI 服务模拟：保留加载延迟、置信度、生成依据和事实信号。这样可以演示产品工作流，但不把模拟结果误认为真实模型能力。

## 2. 产品主线

```text
客户来源
  ↓
AI 企业候选池
  ↓  AI 清洗、评分、排序、解释
优先客户：星澜智能 StarWave AI
  ↓
个性化联系内容 + 跟进节奏
  ↓
服务方案 + 目标指标
  ↓
执行任务 + 交付样例
  ↓
目标 / 实际复盘
  ↓
下一轮改进任务
```

产品角色是“出海营销服务商”，潜客对象是“可能需要出海营销服务的 AI 企业”，不是海外终端买家。

案例主线由 `MarketingCase.leadId` 固定，当前 Demo 使用“星澜智能 · 东南亚 GTM 验证”作为主案例。左侧五个菜单和顶部案例条共同表达当前案例走到哪一步。

## 3. Demo 功能边界

### 3.1 本次实现

| 模块 | 实现内容 |
|---|---|
| 客户获取 | 线索来源字段、来源筛选、模拟同步 2 家新 AI 企业 |
| 潜客分析 | 5 家初始 AI 企业、匹配度排序、来源信号、五维评分、AI 分析抽屉 |
| 案例选择 | 将任意客户设为本轮案例，更新全局案例条 |
| 客户联系 | 邮件 / LinkedIn / WhatsApp 草稿、AI 依据、可编辑内容、结构化跟进步骤 |
| 方案撰写 | 客户现状、目标、策略、交付物、周期、目标指标、复制方案 |
| 执行交付 | AI 拆解任务、任务状态、交付物入口、邮件/表格/列表/指标样例预览 |
| 数据复盘 | 渠道表现、目标 vs 实际、达成状态、复盘依据、下一轮任务 |
| 工程结构 | `api/client.ts` 作为 Mock API 与视图之间的替换点 |

### 3.2 本次不实现

- 真实后端、数据库、登录、权限、多租户
- 真实 LLM 调用和 Prompt 管理
- 直接爬取 LinkedIn、Google、B2B 平台或个人联系方式
- 自动群发邮件、LinkedIn 私信或 WhatsApp 消息
- Excel/PDF 导出，Demo 先支持复制 Markdown/文本
- 复杂的多案例并行管理

真实项目中，客户数据应优先来自官网表单、CRM、展会报名、用户授权的数据接口和公开企业信息，并遵守平台规则及隐私要求。本 Demo 的“导入线索”明确标记为模拟数据源。

## 4. 技术栈与架构

### 4.1 技术栈

- Vue 3 `<script setup>`
- TypeScript + `vue-tsc`
- Vite

## 5. 数据模型

### 5.1 客户与来源

`Lead` 代表可能需要出海营销服务的 AI 企业，核心字段包括：

- `aiCategory`：AI 客服、AI 数字人、AI 招聘等赛道
- `fundingStage`：Seed、A 轮、B 轮
- `overseasIntent`：出海意图和当前阶段
- `targetMarkets`：目标国家/地区
- `source`、`sourceDetail`、`capturedAt`：客户从哪里来以及采集时间
- `signals`：融资、招聘、官网、活动等可追溯信号
- `fitScore`、`score`：总体匹配度和五维评分

客户来源类型：

```ts
type LeadSource =
  | '官网询盘'
  | '展会名单'
  | 'CRM 导入'
  | '公开企业信息'
  | 'B2B 平台'
  | 'AI 推荐'
```

### 5.2 案例

`MarketingCase` 是五个环节共享的主轴：

- `leadId`：案例对应的客户
- `round`：当前复盘轮次
- `stage`：潜客分析、首次触达、方案确认、执行交付、数据复盘
- `targetMarkets`、`goal`：案例目标市场和目标

### 5.3 AI 分析

每一个 Mock AI 产出保留三类可解释信息：

| 字段 | 用途 |
|---|---|
| `confidence` | 生成结果的参考置信度 |
| `reasons` / `rationale` | AI 为什么这样判断或生成 |
| `evidence` / `signals` | 具体来源、日期和事实信号 |

评分拆成：出海意图、付费能力、服务匹配、决策可达、时机五个维度。Demo 不追求模型精度，重点展示“有依据地排序”。

### 5.4 方案与复盘指标

方案使用 `MetricTarget[]`，复盘使用同一组 `MetricKey`，避免方案指标和复盘指标各说一套：

```text
方案目标 → ReviewMetrics.values → MetricComparison → 复盘结论 → Improvement → 下一轮任务
```

当前指标包括曝光量、点击量、有效线索、销售合格线索、触达回复率、内容产出、单条线索成本。单条线索成本使用非零基线，下降型指标按“实际值 ≤ 目标值”判断达成。

### 5.5 交付样例

`DeliverySample` 不是一个占位名称，而是可以被阅读和复制的结构化内容：

- `paragraph`：说明文字
- `list`：内容清单
- `table`：问题地图、渠道周报
- `email`：主题、版本、正文
- `metric`：交付指标

任务通过 `deliverySampleId` 与交付样例关联，执行页点击“查看样例”打开预览抽屉。

## 6. 页面与交互

### 6.1 营销总览 `/overview`

- 展示 AI 企业线索数量、合格线索、回复率
- 展示渠道线索质量
- 展示当前案例、项目进度和最近任务
- 提供进入潜客分析的入口

### 6.2 潜客分析 `/leads`

- 按 AI 赛道、来源、优先级筛选
- 默认按匹配度降序
- “导入线索”模拟同步 2 家新 AI 企业
- “AI 分析”查看五维评分、信号来源和下一步
- “设为案例”更新全局案例主线

### 6.3 客户跟进 `/follow-up`

- 切换邮件、LinkedIn、WhatsApp
- 编辑并保存 AI 联系内容
- 显示生成依据和 AI 置信度
- 跟进节奏以可勾选步骤呈现：第 1 / 4 / 9 天

### 6.4 服务方案 `/proposals`

- 生成或查看方案
- 展示现状、目标、策略、交付物和目标指标
- 复制方案文本
- 确认方案后进入 AI 任务拆解

### 6.5 执行交付 `/tasks`

- 按任务名称和状态筛选
- AI 拆解方案为任务
- 修改任务状态
- 查看问题地图、内容清单、邮件序列和周报等交付样例

### 6.6 数据复盘 `/review`

- 展示渠道表现和 AI 复盘摘要
- 展示基线、目标、实际、达成状态
- 标出未达成指标
- 点击“生成下一轮计划”新增 3 条“AI 复盘”任务，并将案例轮次加 1

## 7. AI 使用位置

| 环节 | AI 做什么 | 人工保留什么 |
|---|---|---|
| 客户获取 | 清洗企业信息、识别出海信号、推荐来源 | 确认数据来源是否合法、是否纳入客户池 |
| 潜客分析 | 五维评分、排序、说明优先级 | 选择本轮案例 |
| 客户联系 | 生成渠道文案和跟进节奏 | 修改事实、语气和承诺，确认后发送 |
| 方案撰写 | 根据分析和联系内容生成初稿、指标 | 确认目标、周期、交付边界 |
| 执行交付 | 根据方案拆任务、绑定交付模板 | 调整负责人、日期和实际内容 |
| 数据复盘 | 对照指标找差距、生成改进动作 | 确认数据真实性和下一轮投入 |

## 8. 接口契约

`src/api/types.ts` 定义 Demo 所需的最小接口，`src/api/client.ts` 暴露实际 API：

```text
getCase / setCaseLead
getLeads / discoverLeads
analyzeLead / generateOutreach
getProposals / generateProposal / updateProposalStatus
getTasks / updateTaskStatus / decomposeTasks
getDelivery
getMetrics / generateReview / generateNextRound
```

Mock API 为每个动作保留 120–760ms 的异步延迟，使加载态和操作反馈在演示中可见。未来接真实服务时，实现同一份 `OverseasApi` 即可替换。

## 10. 演示验收脚本

1. 打开“潜客分析”，确认默认按匹配度展示星澜智能。
2. 点击“导入线索”，选择来源并导入，确认列表新增 2 家 AI 企业。
3. 打开星澜智能的“AI 分析”，查看信号、评分和判断依据。
4. 点击“生成联系内容”，编辑邮件并勾选第 1 天跟进步骤。
5. 进入“服务方案”，查看目标指标并复制方案。
6. 进入“执行交付”，点击任务的“查看样例”，阅读真实交付内容。
7. 进入“数据复盘”，查看目标 vs 实际，确认 5 / 7 项达成。
8. 点击“生成下一轮计划”，进入“执行交付”，确认新增 3 条“AI 复盘”任务。

## 11. 验证与已知取舍

- `npm run build`：必须通过 `vue-tsc --noEmit` 和 Vite 构建。
- 当前已通过构建，ECharts 仍有包体积提示，但已从全量入口改为 `echarts/core` 按模块注册。
- Mock 数据在浏览器刷新后恢复初始状态；本 Demo 不承诺持久化。
- 导入线索是模拟同步，不代表已经接入真实数据源。
- 真实 LLM 接入需要补充服务端密钥托管、Prompt 版本、敏感信息脱敏、超时重试和人工审核。

## 12. 后续升级顺序

1. 接入 CSV/CRM 导入，并保留来源、采集时间和授权记录。
2. 接入服务端线索去重、企业信息补全和真实数据库。
3. 将 Mock AI 替换为服务端 LLM 编排，保留置信度和证据链。
4. 增加真实触达记录、发送审批和渠道回执。
5. 多案例、多用户、权限和数据隔离。
